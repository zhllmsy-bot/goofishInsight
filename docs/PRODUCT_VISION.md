# Goofish Insight 产品愿景（v1.0）

## 一句话愿景

**goofishInsight 的目标是：让买手在首次打开 dashboard 后，能在第一屏直接判断“今天该买、该看、该跳过”，并且能追溯可执行证据。**

## 北极星

- 运营者只需 1 次交互即可进入可行动的机会池（买入/观察/跳过）。
- 每条机会都可解释：来自哪个 SKU 指纹、哪个版本 schema、多少样本、什么时间衰减、为什么这个置信度。
- 以“可复现性”为核心：同样输入，在同一版本下给出稳定可复查的价格与建议。

## 成功定义（v1.0）

1. 数据层的决策单元统一为 **`SKU 指纹 × 成色 × 可靠度`**。
2. UI 主路径统一为 **一行一机会 + 抽屉详情 + 键盘流**。
3. 价格建议默认给出区间 + 置信区间，不直接输出“单点结论”。
4. 配置修改可被审计：任一模板、阈值、权重都能回溯到变更来源（PR / 人工审批 / 变更时间）。
5. 本地可复现：从启动、采集、清洗、建模、刷新到机会产出均有可执行命令记录。

## 核心抽象（不变）

- 数据层唯一抽象：**SKU 指纹 × 成色修正 × Tier 可靠度**
- 交互层唯一抽象：**一行一机会 + 键盘流 + 抽屉详情**
- 视觉层唯一抽象：**Token + 原语 + 复合组件体系 + Bloomberg/Linear 参照系**

## 反目标（v1.0 之前不做）

1. 不做多租户 SaaS / 计费 / 用户权限平台。
2. 不把 Android overlay 作为主链路能力。
3. 不把 LLM 作为规则核心路径，不替代 schema、样本资格、runtime 的确定性逻辑。
4. 不新增可导致采集/分析失真却不透明的“黑盒规则”。
5. 不把“看起来完整”误作“能决策”：所有建议都要有样本依据。

## 交付边界（Local-First）

1. 数据、浏览器会话、模型凭据和凭证配置以本地/自托管为前提。
2. 平台只处理公开列表字段，不处理聊天、私人联系方式、身份证信息等隐私字段。
3. ToS 风险、账号责任和地区合规由使用者在本地边界内承担；仓库通过 LICENSE 和免责声明给出边界说明。

## 价值主张

- 对买手：减少“猜价格”时间，提升低噪声决策速度。
- 对团队：避免维护多套模型定义和页面栈，降低新变更回归成本。
- 对系统：让每次模型/模板迭代都体现在统一的版本化合同与审计链路中。

## v1.0 里程碑（内部对齐）

### Must
- 完成 SKU 指纹与 item_samples 的持久化合同。
- 完成样本可靠度与 Tier 的端到端表达。
- 完成配置页三视图（表格编辑 / YAML / PR 审计）可用链路。
- 机会页保留回归证据，明确不产生 `Tier D` 强买入。

### Nice-to-have
- 冷启动提示带不确定度输出。
- 同类类目扩展覆盖 Camera / 手机 / 二手包。
- 首个 v0.1.0 发布说明可复现执行。
