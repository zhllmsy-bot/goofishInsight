# Catalog 迁移工作方法

更新时间：2026-04-05

这套迁移默认采用下面的工作节奏：

1. 先列完整 TodoList
2. 每次只推进一个最小闭环
3. 每做完一步就立刻自检
4. 如果自检暴露新风险，先更新 TodoList，再继续
5. 能沉淀成长期资产的内容必须顺手沉淀

## 具体要求

- 代码改动优先配测试
- 涉及迁移的动作优先提供 `dry-run`
- 每个阶段都要有可重复执行的 CLI 或 SOP
- 每轮关键结论同步写入项目文档
- 每轮里程碑总结同步写入 OpenViking

## 为什么这样做

- 避免“想到哪改到哪”
- 避免未验证就直接 apply
- 避免做完一轮后没有沉淀，下一轮重复踩坑
- 让迁移状态对人和对机器都可见

## 适用范围

- 商品属性系统迁移
- 旧表到新模型 backfill
- 模板升级与对账
- 任何长链路、可回滚、需要多轮验证的工程任务
