# 项目立项

## 1. 项目背景

我们希望围绕闲鱼的公开商品列表，建立一套小规模、可回溯、可分析的数据闭环，用于识别指定品类里的可行动买入机会，并把结果展示为可执行的买方工作台。

项目不追求一开始就全站覆盖，而是从少量品类和 1000+ 条样本起步，先验证采集可行性、分析价值和展示方式。

## 2. 项目目标

- 建立浏览器驱动的数据采集闭环。
- 对公开列表响应进行结构化解析和标准化存储。
- 形成围绕合理价、买入上限、风险和机会的决策模型。
- 构建一套适合买方判断的前端工作台。
- 支撑二手买入决策，优先筛出值得立即关注的目标商品。

## 2.1 首批监控范围

首批只聚焦两个方向：

- 佳明手表
- 苹果 M 芯片系列电脑

项目第一阶段不预设哪一款是当前交易量最高或溢价最高，而是通过采集样本和分析结果去验证。

## 3. 核心问题

- 指定品类当前有哪些稳定可采集的公开字段。
- 指定品类的价格分布和供给结构是什么。
- 哪些卖家、关键词、品牌和型号在样本里更活跃。
- 哪些价格带最拥挤，哪些商品存在异常定价。
- 同一类商品在时间维度上是否存在明显波动。
- 某条商品的合理价和买入上限是多少。
- 哪些商品更接近“值得立即关注”的买入机会。

## 4. 范围定义

### 纳入范围

- 指定品类的公开搜索结果和公开商品详情。
- 公开可见的标题、价格、文案、图片、标签、地区、发布时间、卖家公开信息。
- 原始接口响应存档、标准化表、分析结果表、前端展示。
- 针对佳明手表与苹果 M 芯片电脑的型号级分析和选品排序。

### 不纳入范围

- 聊天内容、手机号、地址、实名、设备指纹、账号敏感信息。
- 非公开接口逆向重放体系。
- 高并发或大规模无人值守采集。

## 5. 使用对象

- 项目发起人：定义品类、判断业务价值。
- 数据分析者：查看结果、建立指标、做专题研究。
- 前端消费者：通过 Web 面板快速读取结论和明细。

## 6. 成功标准

- 至少 3 个品类可稳定采集。
- 单轮采集后可拿到 1000+ 条有效样本。
- 原始响应和标准化数据可一一回溯。
- 前端可完成品类概览、明细浏览和基础趋势展示。
- 能输出一份面向二手交易的型号优先级名单。
- 每条买入机会至少能从合理价、折价和风险三个维度解释其进入依据。

## 7. 关键约束

- 必须基于浏览器正常行为发起请求。
- 必须保留采集频率和批量规模的节制。
- 必须避免采集和展示个人敏感信息。
- 必须接受样本不是全市场全量成交数据这一现实。
- 必须支持远程部署和外部访问查看分析结果。

## 8. 风险清单

- 登录态过期导致采集任务中断。
- 页面结构调整导致监听逻辑失效。
- 字段漂移导致解析结果缺失或混乱。
- 样本偏差导致分析结论失真。
- 平台规则变化影响采集稳定性。

## 9. 项目阶段

- P0：立项与方案冻结
- P1：采集闭环 PoC
- P2：分析指标成型
- P3：Web 看板上线

## 10. 基础设施决策

- 数据库直接采用 PostgreSQL，不走 SQLite 过渡。
- 部署目标是远程服务器，通过 Docker Compose 管理。
- 面向外部访问的入口优先是 Web 页面，不直接对公网暴露 PostgreSQL。
