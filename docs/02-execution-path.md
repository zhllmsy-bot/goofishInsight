# 执行路径

## 1. 总体执行思路

项目执行链路遵循一个原则：让浏览器正常加载页面和触发翻页动作，系统只负责监听列表接口响应、提取结构化数据并落库。

## 2. 端到端链路

```mermaid
flowchart LR
  A["品类/关键词配置"] --> B["Playwright 打开页面"]
  B --> C["人工登录或复用持久化会话"]
  C --> D["触发搜索/翻页/滚动"]
  D --> E["监听目标列表接口响应"]
  E --> F["原始响应落库"]
  F --> G["标准化字段解析"]
  G --> H["分析指标计算"]
  H --> I["前端可视化展示"]
```

## 3. 执行分层

### 3.1 任务配置层

- 定义品类、关键词、筛选条件、抓取页数、抓取频率。
- 为每个采集任务分配唯一 task key。
- 为佳明手表和苹果 M 芯片电脑分别维护关键词与型号词表。

### 3.2 采集执行层

- 启动持久化浏览器上下文。
- 进入目标搜索页或频道页。
- 触发翻页、滚动或筛选变化。
- 监听目标接口响应并抓取响应体。

### 3.3 数据落库层

- 写入采集运行表。
- 写入原始请求和原始响应。
- 提取商品主字段并写入标准化商品表。
- 所有写入统一进入 PostgreSQL。

### 3.4 分析计算层

- 生成价格分布、品牌分布、卖家活跃度等聚合指标。
- 计算专题分析需要的衍生字段。

### 3.5 展示消费层

- 前端读取分析结果接口。
- 渲染概览、列表、趋势和专题页。

## 4. 第一期执行步骤

1. 固定首批监控方向：佳明手表、苹果 M 芯片电脑。
2. 为每个方向拆出关键词、品牌词、型号词和配置词。
3. 通过 Playwright 监听列表接口响应。
4. 落原始响应和标准化商品记录。
5. 完成第一轮分析脚本。
6. 完成第一版 Web 看板。

## 5. 运行边界

- 起步只做小样本、低频运行。
- 允许人工介入登录。
- 允许人工复核字段映射。
- 不在第一期追求消息队列和复杂容灾。
- 第一阶段部署在单台远程服务器即可。

## 6. 需要尽早验证的技术点

- 列表接口在翻页时是否稳定。
- 是否存在无限滚动替代页码分页。
- 响应中是否带完整商品核心字段。
- 登录态保留时间和任务可持续时长。
- 同一个商品是否会在多次采集中重复出现。
- 标题里是否能稳定抽出 Garmin 型号、Apple 芯片代际、内存和硬盘规格。
